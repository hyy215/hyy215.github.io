ui-forge 设计接入与规则配置 ​

设计接入决定任务读取哪份设计，规则配置决定页面按什么要求实现。ui-forge 在创建任务时确定这两项，后续继续任务时沿用原来的设计绑定和规则。

设计从哪里来 ​

来源接入方式主要约束
本地输入（local）图片或文字不启用内置 MasterGo 接入
MasterGo Magic官方远程 MCP 服务需要凭据和设计访问权限
MasterGo Vibe经 ui-forge 适配层访问 MasterGo 本机服务需要打开指定文件和页面，并提供目标图层

启动任务前，可以通过页面的“检查连接”或 CLI 的 design-check 提前发现连接失败、工具缺失或画布不匹配等问题。

  • Magic 通过设计链接定位目标，不依赖本机画布，预检只检查连接和工具清单。
  • Vibe 依赖 MasterGo 当前打开的文件和页面，因此还会核对画布，并检查工具是否支持所需的 JSON 数据读取。

预检不创建任务、不调用模型，也不会为任务占用 Vibe 服务。创建任务时会重新检查，目标设计能否实际读取则在执行时访问设计后确认。源码：连接预检

创建任务时，本地服务会保存所选的设计来源和接入方式，后续继续任务时沿用这份设计绑定。Vibe 接入还有以下约束：

场景处理方式
固定设计目标创建时记录文档、页面和图层；继续执行时核对原绑定，读取前后也检查画布，目标不一致时要求恢复原画布。源码：设计绑定
避免任务抢占原任务仍在运行或等待交互时，其他任务不能占用同一个 Vibe 服务；无法确认状态时也不放行。源码：使用权检查
只读访问ui-forge 的适配服务只提供 read_design，不开放画布修改或删除工具，因此称为“只读桥”。源码：只读桥
查看历史、诊断或停止任务不要求 Vibe 在线；只有继续执行或读取设计时，才检查画布和使用资格。

设计绑定不保存内容副本，同一页面被修改后仍可能读到新内容。“只读”也仅针对设计画布，不影响 Codex 在授权范围内修改目标项目代码。

规则如何配置和生效 ​

默认设计与出码约束 ​

ui-forge 内置两份规则。未自定义时使用内置内容，主要要求如下，完整规则可点击文件名查看：

规则文件默认要求举例
design.md按设计还原布局和状态；实现搜索、切换、编辑等常规交互；不编造业务结果；在真实浏览器中检查视觉和交互
project.md使用 React + TypeScript，复用项目结构和合适组件；按职责组织代码和状态，限制样式作用域；不擅自增加后端接入或无关重构；完成相关工程检查

默认不强制使用 Ant Design，也不把页面当成纯静态图片实现；用户明确要求静态稿时才省略交互。严格像素验收需要在任务中明确启用，具体比较方法见验收验证与任务诊断。

修改后的规则何时生效 ​

用户可以在配置页编辑并保存两份规则，页面和 CLI 创建的新任务共用保存后的内容。读取或保存失败会明确报错；指定的自定义文件不存在时，也不会悄悄退回默认规则。源码：规则读写

规则在新任务创建时交给 Codex，已有会话不会因文件被修改而自动换用新规则。例如，任务 A 创建后修改了规则，之后创建的任务 B 使用新内容，继续任务 A 则仍沿用原规则。

这些规则是交给 Codex 的实现要求，不是保证结果合格的自动检查，也不会扩大沙箱或审批权限。是否符合要求，仍要看实际验证结果。

规则怎样传给 Codex

prepareD2C 读取两份规则，将全文放入新会话的 developerInstructions，同时记录 SHA-256 内容指纹，用于比对规则是否相同，不能用来还原正文。恢复旧会话时只重新准备 Skill、MCP 和临时目录，不用当前规则文件覆盖原会话。源码：规则加载
