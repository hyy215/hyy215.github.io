ui-forge 项目架构 ​

项目定位 ​

代码仓库：hyy215/ui-forge。本文基于 2026-09-22 的提交 4fbf47d 讲解。

ui-forge 面向 React + TypeScript 中后台项目，支持从 MasterGo 设计链接、参考图和需求生成页面，提供 VS Code 插件页面和命令行（CLI）两个入口。

ui-forge 复用 Codex 的会话和执行能力，不另建一套执行引擎。Codex 负责读设计、查代码、编码和验证，ui-forge 负责将这些能力接入开发环境，让用户能够提交任务、查看执行过程、处理审批，并从不同入口继续同一个任务。

任务如何流转 ​

页面和 CLI 连接同一个 ui-forge 本地服务（Agent Server），由它统一管理 Codex App Server 进程、会话和审批。在页面中创建的任务，也可以通过 CLI 继续。只要本地服务和对应的 Codex 进程仍在运行，关闭页面或退出 CLI 就不会主动停止任务。读取设计、修改代码和操作浏览器，则由 Codex 调用相应工具完成。

下面从用户提交任务开始，沿着请求和回复看一次完整交互。图中的“项目与工具”合并表示目标项目文件、终端、设计工具和浏览器。

进度会随执行持续上报，审批也可能发生在任意需要授权的操作前，并不限于图中的位置。具体验证和修复由 D2C Skill（任务指导与配套脚本）及规则引导，不是本地服务按固定步骤调度。

最终代码留在目标项目，页面和 CLI 展示的是执行记录与结果。本轮结束不等于验收通过：交付说明仍要区分已验证、失败、未验证和受阻的内容。用户继续提出修改时，沿同一条路径发送输入；运行中补充给当前轮次，空闲时在原会话中启动新一轮。

关键设计 ​

创建任务时，ui-forge 根据设计来源配置工具，并将设计规则和工程规范交给 Codex。何时读取设计、修改哪些文件、如何验证，由 Codex 结合需求和现有项目决定。

会话历史由 Codex 保存。ui-forge 通过任务索引关联目标项目、设计绑定和会话，并保存图片附件和诊断等辅助数据。重新打开任务时，ui-forge 读取历史并衔接后续消息；本地服务重启后则重新加载会话。加载会话本身不会启动新一轮执行，后续修改仍需用户发起。

实现参考 ​

代码模块与职责
模块主要职责
agent-webview设计输入、任务时间线、审批、规则编辑和诊断展示
vscode-extension承载 Webview，绑定当前工作区并转发请求
agent-cli命令行输入输出、任务列表、继续和停止
agent-server托管 Codex 进程，维护任务索引、连接、事件和设计绑定
codex-client读取配置和规则，启动 Codex，校验原生请求与事件
client-core消费消息流，将快照和后续事件合并成展示状态
shared-protocol定义 ui-forge 各入口与 Server 之间的通信格式

Webview 通过 Extension 访问本地服务，CLI 直接连接本地服务，使用 HTTP 与 NDJSON 消息流；本地服务通过 codex-client，使用标准输入输出上的 JSONL 与 Codex App Server 通信。NDJSON 和 JSONL 都按行传送 JSON 消息。

本文版本中，ui-forge 客户端与 Server 的通信协议为 22。它与 Codex 原生协议是两层协议；原生消息使用生成的 Schema（数据结构校验规则）验证。

Codex 接口与 ui-forge 命令速查

RPC 是通过方法名和参数发起调用、再接收结果的通信方式。下面列的是本项目使用的 Codex App Server 原生接口，不是 ui-forge 自己实现的会话引擎。

方法用途
initialize建立连接后握手，提交客户端信息和能力声明
config/read读取配置，检查 MCP、Agent 等运行设置
skills/extraRoots/set把 ui-forge 自带的 D2C Skill 注册给 Codex
account/read检查登录信息；本项目调用时不刷新登录凭据
thread/start创建一个新的 Codex 会话，返回 thread.id
thread/resume把已有会话装载到当前连接，不重放旧输入，也不启动新轮次
thread/read读取会话快照和历史；页面恢复、状态查看和诊断都会用到
thread/list查找主线程下的子线程，补充诊断报告
turn/start在会话中启动新一轮，传入文字、图片，并附加临时产物目录说明
turn/steer给正在运行的轮次补充输入，不创建新的轮次
turn/interrupt停止指定的运行中轮次

通信还有另外两个方向：Codex 会推送进度通知，也会发出需要回复的请求。

类型原生方法ui-forge 怎么处理
会话和轮次通知thread/started、thread/status/changed、turn/started、turn/completed更新展示状态
执行项和用量通知item/*、thread/tokenUsage/updated展示过程，记录用量观测
操作审批item/commandExecution/requestApproval、item/fileChange/requestApproval、item/permissions/requestApproval展示操作范围，校验并回传用户决议
提问和表单item/tool/requestUserInput、mcpServer/elicitation/request收集回答，按对应格式回复

通知不需要用户回应；审批、提问和表单是服务端请求，要用原始 request ID 回传结果。

终端里的 ui-forge 子命令是项目自己的入口，和上述原生接口不是一回事：

  • run 创建任务，list 列出任务，status 读取快照。
  • resume 连接原任务，并在空闲时发送继续请求；不等于只调用 thread/resume。
  • diagnostics 输出诊断，design-check 只读检查设计接入。
  • doctor 检查 Codex 版本和登录状态，serve 启动本地服务。

sessionService.ts 负责会话操作，codexClient.ts 负责原生通信适配；两层协议分别见 shared-protocol 和生成的 NativeMethods。

文中的任务工作方式和交付要求见 D2C Skill。
