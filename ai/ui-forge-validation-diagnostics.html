ui-forge 验收验证与任务诊断 ​

模型说“完成了”，不代表页面真的能交付。ui-forge 把验收证据和运行诊断分开：前者看页面结果，后者看任务过程。

页面如何验收 ​

页面需要从工程、交互和视觉三个方面检查，并保留对应证据：

层次证据解决的问题
工程类型检查、构建和相关测试的输出对应检查是否通过
交互真实浏览器中的操作结果和测试记录点击、输入、取消和恢复是否符合要求
视觉参考图、浏览器截图及按需生成的差异图布局、样式和页面状态是否符合设计

任务规则要求 Codex 运行相关工程检查，再在浏览器中验证页面；发现问题后修改代码，并复查受影响的部分。交付时说明已验证、失败、未验证和受阻的项目，并附上测试输出、截图或报告。源码：D2C 验证与交付要求

这不是 Server 在每轮结束后自动执行的固定流水线。具体工具由 Codex 根据任务选择，completed 只表示本轮执行结束，不能代替验收结论。

截图如何比较 ​

先保证两张图可以对照 ​

只有任务明确要求严格像素验收时，才使用比较脚本。未启用时，仍需按设计规则进行浏览器视觉检查。

比较前，需要确认参考图可靠，两图的像素尺寸一致，并对应相同的视口和页面状态。截图前应等待字体与图片加载完成，并禁用动画。例如，参考图展示了悬停状态，实际截图也应通过真实操作进入该状态。脚本只读取图片，不能替浏览器判断这些条件是否满足；缺少条件时应说明受阻原因。

按像素差异判断 ​

脚本使用 Python + Pillow 图像处理库，不是让 AI 给图片打分。它将两张图转成 RGBA，即红、绿、蓝和透明度四个通道，再比较同一位置各通道的数值差异：

脚本不会自动缩放或裁切图片，尺寸不一致时直接判为失败。尺寸相同时，只要某个像素的任意通道差值超过容差，就把它计为差异像素，再看两个指标：

  • 全图差异像素比例：整体有多少像素不同。
  • 最大连通区域占比：最大一块相连差异占全图的比例，用来发现集中在局部的问题。

启用严格像素验收，且任务未指定其他阈值时，内置设计规则采用以下默认值：

参数默认值含义
通道容差8任意通道差值大于 8，该像素就算不同
全图差异像素比例上限1%差异像素占比不得超过 1%
最大连通区域占比上限0.1%最大一块相连差异不得超过全图的 0.1%

这些是规则约定，调用脚本时仍需显式传入，并非脚本自行填入的默认参数。源码：严格像素验收规则

脚本保存差异图，并向终端输出 JSON 比较结果，由调用方保存为报告；尺寸不一致时只报告失败，不生成差异图。比较通过只说明满足这组像素阈值，不能换算成“设计还原度”，也不能替代交互和工程检查。源码：截图比较脚本

相连区域怎么算，返回码怎么看

脚本通过广度优先搜索（BFS）统计相连区域：上下左右和四个斜角相邻的差异像素归为同一块，即“八邻域”。报告记录区域的位置、尺寸和面积，但不会识别按钮或文字等组件。

返回码 0 表示比较通过，1 表示未通过，2 表示参数、依赖或读写错误。

任务异常如何排查 ​

任务失败、耗时异常，或需要核对运行配置时，可以打开页面的“任务诊断”，也可以使用 CLI 的 diagnostics TASK_ID。两种入口读取同一份诊断摘要，还可以导出 JSON 供排查使用。

想了解什么查看哪些信息
任务使用了什么配置模型、Codex 版本、运行配置和规则指纹
哪些执行环节出了问题轮次状态、错误类别、工具完成和失败统计、子任务摘要
执行花了多少时间和 Token轮次耗时、已记录的工具耗时和 Token 用量

诊断提供排查线索，不会自动解释所有失败原因，也不会替用户重跑任务。源码：诊断报告生成

数字的统计范围 ​

报告包含主会话和子任务摘要，但并不是所有数字都汇总了它们：

  • 轮次和工具统计来自主线程，子代理另列摘要。
  • Token 使用主线程最后一次观测到的累计值，不重复累加通知，也不汇总子线程。
  • 工具可能并行执行，因此不能把工具耗时之和当作整轮执行耗时。
  • 未采集到的信息显示未知，不补成零，也不用当前规则冒充历史规则。

报告只输出预先允许的字段，不包含需求正文、规则全文、代码、命令输出、MCP 参数或审批凭据。要查看具体执行内容，仍需回到任务记录。

诊断数据如何读取

SessionService.readDiagnostics() 根据任务索引定位会话，用 thread/read 读取主线程历史，再用 thread/list 查找子线程，并合并独立保存的运行配置、规则指纹和 Token 观测。

查询不调用 thread/resume 或启动新轮次；必要时仍会建立 Codex 通信连接。主线程历史读取失败时直接报错；子线程查询或辅助元数据不可用时，可以返回报告并标注缺失信息，不会改走会话恢复流程。源码：诊断读取

ui-forge 自身如何验证

下面是工具本身的测试覆盖，不是生成页面的验收结果：

测试检查内容
比较器测试相同图、对角相连差异、尺寸不符和无效阈值
Server 诊断测试不恢复或启动会话、Token 累计值更新、敏感内容过滤和元数据失败
Webview E2E诊断弹窗、导出、失败重试和窄屏交互
live 协议测试真实 Codex 的编码、审批、停止和恢复链路

具体执行结果应以对应测试记录为准。比较器测试缺少 Python/Pillow 时会跳过，live 测试需要显式启用。这些测试不能直接证明页面还原质量或效率提升；评估实际效果需要固定任务集、模型、规则和环境，再对照通过率、失败原因、耗时和 Token。
