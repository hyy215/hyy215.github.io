Koa 洋葱模型（源码解析，简约版） ​

📅 2020-04-12Koa中间件compose源码阅读

本文通过一个最小示例，说明 Koa 中间件为什么会按“先向下游进入，再向上游返回”的顺序执行。

经典示例 ​

js
const Koa = require('koa');
const app = new Koa();

app.use(async (ctx, next) => {
  console.log('1');
  await next();
  console.log('1-1');
});

app.use(async (ctx, next) => {
  console.log('2');
  await next();
  console.log('2-1');
});

app.use(async (ctx, next) => {
  console.log('3');
  await next();
  console.log('3-1');
});

app.listen(3000);

Koa 的请求调用链 ​

Koa 的中间件会先组合成一个函数，再在每次请求到来时传入当前 ctx 执行。Koa 3.2.1 的 Application 源码 可简化为以下调用链：

js
listen(...args) {
  const server = http.createServer(this.callback());
  return server.listen(...args);
}

callback() {
  // 创建 HTTP Server 时先将中间件组合成 fn
  const fn = this.compose(this.middleware);

  // 返回给 http.createServer() 的请求处理函数
  return (req, res) => {
    const ctx = this.createContext(req, res);
    return this.handleRequest(ctx, fn);
  };
}

handleRequest(ctx, fnMiddleware) {
  const onerror = (err) => ctx.onerror(err);
  const handleResponse = () => respond(ctx);

  // 每次请求都会传入当前 ctx 执行中间件链
  return fnMiddleware(ctx).then(handleResponse).catch(onerror);
}

  • app.use(fn) 将中间件保存到 this.middleware；Koa 会拒绝非函数参数，并返回 this 以支持链式调用。
  • app.listen(3000) 使用 http.createServer(this.callback()) 创建 HTTP Server。
  • callback() 调用 compose(this.middleware) 得到 fn，然后返回真正的 HTTP 请求处理函数。
  • 每次请求到来时，Koa 会创建 ctx，再由 handleRequest(ctx, fn) 执行 fn(ctx)。

koa-compose 如何调度中间件 ​

官方 koa-compose 4.1.0 的核心实现如下。为了聚焦调度过程，这里省略了对 middleware 数组及其成员类型的前置校验。

js
function compose(middleware) {
  return function (context, next) {
    let index = -1;
    return dispatch(0);

    function dispatch(i) {
      if (i <= index) {
        return Promise.reject(new Error('next() called multiple times'));
      }

      index = i;
      let fn = middleware[i];

      // 所有中间件执行完后，fn 变为外部传入的 next
      if (i === middleware.length) fn = next;
      if (!fn) return Promise.resolve();

      try {
        return Promise.resolve(fn(context, dispatch.bind(null, i + 1)));
      } catch (err) {
        return Promise.reject(err);
      }
    }
  };
}

compose(this.middleware) 返回组合后的中间件函数 fn。每个中间件收到的 next 实际是绑定了下一个索引的 dispatch：

js
dispatch.bind(null, i + 1)
1

调用 next() 会执行 dispatch(i + 1) 并返回下游中间件的 Promise。await next() 使当前中间件暂停，等待下游全部完成后，再继续执行 await next() 后面的代码。

通过本文开头的例子，我们再来了解下 fn 的执行过程：

js
// dispatch(0)
Promise.resolve((async (ctx, next) => {
  console.log('1');
  await next();
  console.log('1-1');
})(context, dispatch.bind(null, 1)));

// dispatch(0) 中的入参 next 为 dispatch.bind(null, 1)
// 所以 next() 相当于执行 dispatch(1)
Promise.resolve((async (ctx, next) => {
  console.log('2');
  await next();
  console.log('2-1');
})(context, dispatch.bind(null, 2)));

// dispatch(1) 中的入参 next 为 dispatch.bind(null, 2)
// 所以 next() 相当于执行 dispatch(2)
Promise.resolve((async (ctx, next) => {
  console.log('3');
  await next();
  console.log('3-1');
})(context, dispatch.bind(null, 3)));

错误捕获 ​

compose 会把中间件同步抛出的错误转换为 rejected Promise。如果错误沿中间件 Promise 链向上冒泡，且没有被上游中间件处理，最终会进入 handleRequest() 的 .catch(onerror)，由 ctx.onerror(err) 生成错误响应并触发应用级 error 事件。

上游中间件也可以自行捕获下游错误：

js
app.use(async (ctx, next) => {
  try {
    await next();
  } catch (err) {
    ctx.status = err.status || 500;
    ctx.body = { message: err.message };
  }
});

防止重复调用 next() ​

compose 内部维护了一个 index 变量，每次进入 dispatch(i) 时都会检查：

js
if (i <= index) return Promise.reject(new Error('next() called multiple times'))
1

这防止了同一个中间件多次调用 next()：

js
app.use(async (ctx, next) => {
  await next();
  await next(); // 错误：next() called multiple times
});

如果允许重复调用，后续中间件会被执行多次，响应体、数据库写入等副作用都会变得不可预测。

总结 ​

  • callback() 在创建 HTTP Server 时先组合中间件，每次请求再通过 handleRequest(ctx, fn) 执行中间件链。
  • next 是绑定了下一个索引的 dispatch；await next() 同时建立了向下游进入和向上游返回的执行顺序。
  • 只有沿 Promise 链继续冒泡的错误才会到达 Koa 的应用级错误处理；index 检查则用于阻止同一个 next() 被重复调用。
