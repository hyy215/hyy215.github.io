AVL 树：旋转与再平衡 ​

AlgorithmTypeScriptAVL 树

普通二叉搜索树只规定键值顺序，不限制树的形状，其操作复杂度取决于树高：形状较平衡时，搜索、插入和删除为 O(log n)；连续插入有序数据时，树可能退化成链表，最坏达到 O(n)。

AVL 树在二叉搜索树之上增加对子树高度的约束：每次更新后维护节点高度，并通过局部旋转恢复平衡。本文使用 TypeScript 实现搜索、插入和删除。

AVL 树约束了什么 ​

Adelson-Velskii 和 Landis 在 1962 年提出的结构要求：对树中的每个节点，左、右子树的高度差不超过 1。

本文采用按节点层数计算高度，与二叉树基础篇按边计算高度的定义不同

  • 空树高度为 0；
  • 叶节点高度为 1。

本文将平衡因子定义为左子树高度减右子树高度：

text
balanceFactor(node) = height(node.left) - height(node.right)
1

因此，一个有效 AVL 节点的平衡因子只能是 -1、0 或 1。

需要注意，AVL 比较的是子树高度，不是左右节点数量。下面这棵树的左右节点数不同，但仍然满足 AVL 约束：

      /   \
     4     12
    / \    /

为什么树高是 O(log n) ​

设高度为 h 的 AVL 树至少包含 N(h) 个节点。为了让节点尽可能少，同时保持根节点高度为 h，两棵子树的高度应分别为 h - 1 和 h - 2：

text
N(h) = 1 + N(h - 1) + N(h - 2)
1

这个递推关系按斐波那契数列的速度增长，所以节点数随高度呈指数增长；反过来，高度随节点数按对数增长。

Princeton 的平衡搜索树讲义采用按边定义高度，给出的上界小于约 1.4404 log₂ n。本文采用按节点层数计算高度，同一棵树的高度比按边定义多 1，因此对应的上界小于约 1.4404 log₂ n + 1。

无论采用哪种高度定义，AVL 树的高度都是 O(log n)，因此沿根到叶路径完成的搜索、插入和删除也都是 O(log n)。

节点表示与高度维护 ​

每个节点除了值和左右子节点，还保存以当前节点为根的子树高度：

ts
class AVLNode {
  height = 1
  left: AVLNode | null = null
  right: AVLNode | null = null

  constructor(public value: number) {}
}

在后续操作中，我们还需要维护节点记录的高度，因此先定义读取高度、更新高度和计算平衡因子的函数：

ts
function height(node: AVLNode | null): number {
  return node?.height ?? 0
}

function updateHeight(node: AVLNode): void {
  node.height = 1 + Math.max(
    height(node.left),
    height(node.right)
  )
}

function balanceFactor(node: AVLNode): number {
  return height(node.left) - height(node.right)
}

什么是旋转 ​

旋转是二叉搜索树的一种局部结构调整，分为右旋和左旋。

调整只涉及固定数量的节点和引用，不会增删节点或改变原有键值。

右旋 ​

以 y 为原来的子树根，右旋可以分为三步：

  1. 选择 y 的左子节点 x，并暂存夹在两者中间的子树 B；
  2. 让 x 上升为新的子树根，让 y 下降为 x 的右子节点；
  3. 将子树 B 接到 y 的左侧，填补 x 上升后空出的位置。

function rotateRight(y: AVLNode): AVLNode {
  const x = y.left!
  const subtreeB = x.right

  y.left = subtreeB
  x.right = y

  updateHeight(y)
  updateHeight(x)
  return x
}

共同规则 ​

右旋和左旋的方向不同，但都遵循以下规则：

  1. 让选中的子节点上升为新的子树根；
  2. 让原来的子树根下降为它的子节点；
  3. 将夹在两者之间的子树转移给下降的节点，填补空出的子节点位置；
  4. 用新的子树根替换原子树在父节点或整棵树根引用中的位置。

一次旋转只读写固定数量的节点和引用，时间复杂度为 O(1)。

旋转为什么不破坏搜索顺序 ​

旋转通过调整局部树形，为恢复高度平衡创造条件。

对二叉搜索树进行旋转时，只会调整局部连接，不会改变中序遍历得到的键值顺序。因此，左子树中的键值仍小于根节点，右子树中的键值仍大于根节点，旋转后的树依然是二叉搜索树。

四种情况可以收敛到一个统一的再平衡函数：

ts
function rebalance(node: AVLNode): AVLNode {
  // 子节点可能已经变化，先更新当前节点的高度
  updateHeight(node)
  const factor = balanceFactor(node)

  // 左侧过高：LL 或 LR
  if (factor > 1) {
    // LR：先将左子树左旋，转换为 LL
    if (balanceFactor(node.left!) < 0) {
      node.left = rotateLeft(node.left!)
    }
    // LL：对当前节点右旋
    return rotateRight(node)
  }

  // 右侧过高：RR 或 RL
  if (factor < -1) {
    // RL：先将右子树右旋，转换为 RR
    if (balanceFactor(node.right!) > 0) {
      node.right = rotateRight(node.right!)
    }
    // RR：对当前节点左旋
    return rotateLeft(node)
  }

  // 当前节点没有失衡
  return node
}

插入后如何恢复平衡 ​

AVL 插入分为两个阶段：

  1. 向下查找：按照普通二叉搜索树的插入规则找到新节点的插入位置
  2. 向上回溯：沿原搜索路径依次更新祖先的高度，并修复失衡。

代码中的递归调用负责向下查找，return rebalance(node) 负责在回溯时重新平衡当前子树：

ts
function insertNode(
  node: AVLNode | null,
  value: number
): AVLNode {
  if (!node) return new AVLNode(value)

  if (value < node.value) {
    node.left = insertNode(node.left, value)
  } else if (value > node.value) {
    node.right = insertNode(node.right, value)
  } else {
    return node
  }

  return rebalance(node)
}

新增叶节点后，只有从该叶节点到根节点的搜索路径可能受到影响，路径之外的子树既没有改变连接，高度也不会变化。因此，递归返回时只需要沿原搜索路径自底向上处理各个祖先：

  1. 更新当前节点的高度；
  2. 计算当前节点的平衡因子；
  3. 如果仍然平衡，继续回溯到它的父节点；
  4. 如果失衡，根据 LL、RR、LR 或 RL 类型执行对应旋转。

时间复杂度：AVL 树的搜索路径长度为 O(log n)，沿路径处理每个祖先只需 O(1) 时间，因此插入的总时间复杂度为 O(log n)。

本文延续二叉树基础篇的约定：遇到重复值时不插入新节点。

为什么只需要修复一个失衡祖先 ​

插入导致的第一个失衡祖先经过一次单旋，或由两次单旋组成的一次双旋后，当前子树会恢复到插入前的高度。它在更高祖先眼中的高度没有继续增加，因此更高的祖先不会再因这次插入而失衡。

递归实现仍会继续回溯到根节点，并重新计算沿途节点的高度和平衡因子；只是这些更高的节点不再需要旋转。

删除后如何恢复平衡 ​

AVL 删除可以分为三个阶段：

  1. 查找目标节点：根据目标值与当前值的大小关系，递归进入左子树或右子树；
  2. 删除目标节点：找到目标节点后，按照普通二叉搜索树的删除规则，根据其子节点情况删除或替换节点
  3. 恢复 AVL 平衡：沿原搜索路径回溯，更新祖先的高度并修复失衡。

普通二叉搜索树删除中，不同节点情况的回溯起点有所不同：

  • 叶节点或只有一个子节点：当前节点会被删除或替换，不需要再对它执行平衡操作；递归返回后，从它的父节点开始向上更新高度并修复失衡；
  • 有两个子节点：当前节点不会被删除，只会用右子树中的最小值替换当前值；随后在右子树中递归查找并删除该最小值。递归返回时，先沿右子树中的删除路径恢复平衡；回到当前节点后，再继续沿当前节点的祖先路径向上恢复平衡。
ts
// 返回当前子树中键值最小的节点
function minimum(node: AVLNode): AVLNode {
  let current = node
  while (current.left) current = current.left
  return current
}

function deleteNode(
  node: AVLNode | null,
  value: number
): AVLNode | null {
  if (!node) return null

  if (value < node.value) {
    node.left = deleteNode(node.left, value)
  } else if (value > node.value) {
    node.right = deleteNode(node.right, value)
  } else {
    // 找到目标节点，执行删除
    // 至多一个子节点：直接用现有子节点替代当前节点
    if (!node.left) return node.right
    if (!node.right) return node.left

    // 有两个子节点：用右子树中的最小值替换当前值，再删除对应节点
    const successor = minimum(node.right)
    node.value = successor.value
    node.right = deleteNode(node.right, successor.value)
  }

  // 沿搜索路径回溯并恢复平衡
  return rebalance(node)
}

为什么可能连续失衡 ​

删除会使受影响路径上的子树变矮。旋转虽然能让失衡节点重新满足 AVL 约束，却不一定能让这棵子树恢复到删除前的高度。如果修复后的子树高度仍比删除前少 1，它的父节点看到的子树高度也会下降，因而可能再次失衡。

这里的两次左旋分别发生在不同祖先 2 和 5，不是同一个失衡节点上的双旋。这个例子说明，删除不能像插入那样在修复第一个失衡祖先后结束，而必须继续回溯到根，并依次更新高度、检查平衡因子和执行必要的旋转。MIT 的 AVL 课程讲解展示了这种自底向上的再平衡过程。

时间复杂度：查找删除位置需要 O(log n)，沿路径更新高度和重新平衡也需要 O(log n)，因此删除的总时间复杂度为 O(log n)。

旋转次数：一次删除最坏可能沿删除位置到根节点的整条路径触发旋转，这条路径的长度最多等于树高。由于 AVL 树的高度为 O(log n)，旋转次数最坏也为 O(log n)。

完整实现 ​

下面把搜索、插入、删除和旋转组合成一个完整实现：

ts
class AVLNode {
  height = 1
  left: AVLNode | null = null
  right: AVLNode | null = null

  // 创建节点并保存键值
  constructor(public value: number) {}
}

class AVLTree {
  private root: AVLNode | null = null

  // 判断树中是否包含指定键值
  has(value: number): boolean {
    this.assertFinite(value)
    let current = this.root

    while (current) {
      if (value === current.value) return true
      current = value < current.value
        ? current.left
        : current.right
    }

    return false
  }

  // 向树中插入指定键值
  insert(value: number): void {
    this.assertFinite(value)
    this.root = this.insertNode(this.root, value)
  }

  // 从树中删除指定键值
  delete(value: number): void {
    this.assertFinite(value)
    this.root = this.deleteNode(this.root, value)
  }

  // 按中序遍历顺序返回所有键值
  toArray(): number[] {
    const result: number[] = []

    // 将当前子树的键值按中序顺序写入结果
    const traverse = (node: AVLNode | null): void => {
      if (!node) return
      traverse(node.left)
      result.push(node.value)
      traverse(node.right)
    }

    traverse(this.root)
    return result
  }

  // 检查整棵树是否满足 AVL 树
  isValid(): boolean {
    return this.validate(this.root, -Infinity, Infinity).valid
  }

  // 读取节点高度，空节点的高度为 0
  private height(node: AVLNode | null): number {
    return node?.height ?? 0
  }

  // 根据左右子树高度更新当前节点高度
  private updateHeight(node: AVLNode): void {
    node.height = 1 + Math.max(
      this.height(node.left),
      this.height(node.right)
    )
  }

  // 计算当前节点的平衡因子
  private balanceFactor(node: AVLNode): number {
    return this.height(node.left) - this.height(node.right)
  }

  // 确保键值是有限数值
  private assertFinite(value: number): void {
    if (!Number.isFinite(value)) {
      throw new RangeError('AVLTree only accepts finite numbers')
    }
  }

  // 对以 y 为根的子树执行右旋
  private rotateRight(y: AVLNode): AVLNode {
    const x = y.left!
    const subtreeB = x.right

    y.left = subtreeB
    x.right = y

    this.updateHeight(y)
    this.updateHeight(x)
    return x
  }

  // 对以 x 为根的子树执行左旋
  private rotateLeft(x: AVLNode): AVLNode {
    const y = x.right!
    const subtreeB = y.left

    x.right = subtreeB
    y.left = x

    this.updateHeight(x)
    this.updateHeight(y)
    return y
  }

  // 根据平衡因子恢复当前子树的平衡
  private rebalance(node: AVLNode): AVLNode {
    this.updateHeight(node)
    const factor = this.balanceFactor(node)

    if (factor > 1) {
      if (this.balanceFactor(node.left!) < 0) {
        node.left = this.rotateLeft(node.left!)
      }
      return this.rotateRight(node)
    }

    if (factor < -1) {
      if (this.balanceFactor(node.right!) > 0) {
        node.right = this.rotateRight(node.right!)
      }
      return this.rotateLeft(node)
    }

    return node
  }

  // 在当前子树中递归插入指定键值
  private insertNode(
    node: AVLNode | null,
    value: number
  ): AVLNode {
    if (!node) return new AVLNode(value)

    if (value < node.value) {
      node.left = this.insertNode(node.left, value)
    } else if (value > node.value) {
      node.right = this.insertNode(node.right, value)
    } else {
      return node
    }

    return this.rebalance(node)
  }

  // 在当前子树中递归删除指定键值
  private deleteNode(
    node: AVLNode | null,
    value: number
  ): AVLNode | null {
    if (!node) return null

    if (value < node.value) {
      node.left = this.deleteNode(node.left, value)
    } else if (value > node.value) {
      node.right = this.deleteNode(node.right, value)
    } else {
      // 找到目标节点，执行删除
      // 至多一个子节点：直接用现有子节点替代当前节点
      if (!node.left) return node.right
      if (!node.right) return node.left

      // 有两个子节点：用右子树中的最小值替换当前值，再删除对应节点
      const successor = this.minimum(node.right)
      node.value = successor.value
      node.right = this.deleteNode(
        node.right,
        successor.value
      )
    }

    // 沿搜索路径回溯并恢复平衡
    return this.rebalance(node)
  }

  // 查找当前子树中键值最小的节点
  private minimum(node: AVLNode): AVLNode {
    let current = node
    while (current.left) current = current.left
    return current
  }

  // 递归检查当前子树并返回校验结果和实际高度
  private validate(
    node: AVLNode | null,
    lower: number,
    upper: number
  ): { valid: boolean; height: number } {
    if (!node) return { valid: true, height: 0 }

    if (
      !Number.isFinite(node.value) ||
      node.value <= lower ||
      node.value >= upper
    ) {
      return { valid: false, height: 0 }
    }

    const left = this.validate(node.left, lower, node.value)
    const right = this.validate(node.right, node.value, upper)
    const actualHeight = 1 + Math.max(left.height, right.height)

    return {
      valid:
        left.valid &&
        right.valid &&
        node.height === actualHeight &&
        Math.abs(left.height - right.height) <= 1,
      height: actualHeight
    }
  }
}

复杂度与适用场景 ​

操作时间复杂度操作额外空间旋转次数
搜索O(log n)迭代实现为 O(1)0
插入O(log n)递归栈 O(log n)最多 2 次单旋
删除O(log n)递归栈 O(log n)最坏 O(log n) 次单旋

这里仅计算一次操作使用的辅助空间，不包括树本身以及每个节点保存的高度字段。

在只比较树高和再平衡开销、其他实现因素相近时，AVL 树更严格的高度限制适合查询频繁、更新相对较少，并且重视最坏查询路径的场景。代价是每个节点需要维护高度，删除后也可能连续旋转；实际性能还会受到内存布局、运行时和具体实现的影响。
