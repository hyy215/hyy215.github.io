统计右侧更小元素：归并排序中的逆序计数 ​

Algorithm归并排序逆序对变体

归并排序 不只能排序，还能在合并的过程中「顺手」统计逆序信息。本题正是逆序对的变体：把暴力的 O(n^2) 降到 O(n log n)，关键就在于 merge 阶段的一次巧妙记账。

本文以 315. 计算右侧小于当前元素的个数 为例，讲清如何在归并排序中边排边数。

题目：315. 计算右侧小于当前元素的个数 ​

给你一个整数数组 nums，返回新数组 counts，其中 counts[i] 表示 nums[i] 右侧严格小于 nums[i] 的元素个数。

查看示例与约束

示例 1

text
输入：nums = [5,2,6,1]
输出：[2,1,1,0]
解释：5 右侧更小的元素是 2 和 1；2 右侧更小的元素是 1；6 右侧更小的元素是 1；1 右侧没有更小的元素。

约束

  • 1 <= nums.length <= 10^5
  • -10^4 <= nums[i] <= 10^4

先从暴力思路出发 ​

最直接的办法：对每个位置 i，向右扫描 j = i + 1 ... n - 1，计数 nums[j] < nums[i] 的个数。

  • 时间复杂度：O(n^2)
  • 空间复杂度：O(1)

当 n 较大时会超时，需要把复杂度降到 O(n log n)。

核心思路：在归并阶段统计跨区间贡献 ​

归并排序会把一个区间拆成左右两半。原数组中，左半段元素的下标一定小于右半段元素的下标，因此 merge 时只要判断右值是否小于左值，就能统计两个区间之间的贡献。

1. 用原下标代替原数组参与排序 ​

nums 保持不变，另外创建一个原下标数组：

text
nums = [5, 2, 6, 1]
idx  = [0, 1, 2, 3]
1
2

归并排序实际移动的是 idx 中的下标：

  • 比较元素时读取 nums[idx[i]]
  • 更新答案时写入 ans[idx[i]]

这样即使元素在排序过程中移动，也能把统计结果写回它在原数组中的位置。

2. 对索引数组执行归并排序 ​

这里采用自顶向下的归并排序，处理过程如下

  1. 递归处理左右半段，使两个区间各自有序。
  2. 每次递归返回时，同一半区间内的「右侧更小元素」已经计入 ans。
  3. 合并两个有序区间时，因为右半段元素在原数组中都位于左半段元素的右侧，所以只需对左半段中的每个元素，统计右半段中有多少个元素比它小。

3. 在 merge 阶段维护 rightCount ​

rightCount 只服务于当前这次 merge，表示已经提前进入结果的右半段元素个数。合并时分为以下情况：

  1. 右值小于左值：先放右元素，并执行 rightCount++。
  2. 右值大于或等于左值：先放左元素，并执行 ans[idx[i]] += rightCount。相等时也先放左元素，保证只统计严格更小的值。
  3. 左半段有剩余：每个剩余左元素都累加当前 rightCount。
  4. 右半段有剩余：直接复制，不再更新答案，因为已经没有左元素需要统计；这些右元素自己的答案已在递归子问题中计算。

为什么同一个 rightCount 可以继续用于后面的左元素？左半段已经升序排列，对于某个提前出列的右元素，有：

text
右元素 < 之前与它比较的左元素 <= 后续左元素
1

因此，这些右元素也一定小于后续尚未出列的左元素。

4. 递归累加完整答案 ​

递归过程中的统计规则如下：

  1. 更深一层递归负责统计左半段和右半段各自内部的答案。
  2. 当前层 merge 只统计左半段元素与右半段元素之间的大小关系。
  3. 对于任意一对原下标 i < j，它们恰好会在某一层 merge 中分居左右两侧。
  4. 如果 nums[j] < nums[i]，右元素会先于左元素出列，并被计入一次。所有递归层的统计结果累加后，就是最终答案。

完整代码 ​

ts
function countSmaller(nums: number[]): number[] {
  const n = nums.length;
  // ans 按原下标保存每个元素右侧更小元素的个数。
  const ans = new Array<number>(n).fill(0);
  // idx 存原下标；归并排序移动的是下标，而不是 nums 中的值。
  const idx = Array.from({ length: n }, (_, i) => i);
  // 复用同一辅助数组，暂存每次 merge 后的下标顺序。
  const temp = new Array<number>(n);

  // 将 idx[l...r] 按对应的 nums 值升序排列，并累计统计结果。
  const mergeSort = (l: number, r: number): void => {
    if (l >= r) return;
    const mid = (l + r) >> 1;

    // 先分别排好左右区间，才能在线性 merge 中统计跨区间贡献。
    mergeSort(l, mid);
    mergeSort(mid + 1, r);

    let i = l;
    let j = mid + 1;
    let k = l;
    // 当前 merge 中，已经提前放入 temp 的右半段元素个数。
    let rightCount = 0;

    while (i <= mid && j <= r) {
      // 严格小于时才先放右元素，避免把相等元素计入答案。
      if (nums[idx[j]] < nums[idx[i]]) {
        temp[k++] = idx[j++];
        rightCount++;
      } else {
        // 已提前放入的右元素都位于当前左元素右侧，且值更小。
        ans[idx[i]] += rightCount;
        temp[k++] = idx[i++];
      }
    }

    // 左半段若有剩余，每个元素都要累加已有的跨区间贡献。
    while (i <= mid) {
      ans[idx[i]] += rightCount;
      temp[k++] = idx[i++];
    }

    // 右半段剩余元素不会再对左元素产生贡献，直接复制即可。
    while (j <= r) {
      temp[k++] = idx[j++];
    }

    // 将合并后的下标顺序写回 idx，供上一层 merge 使用。
    for (let p = l; p <= r; p++) {
      idx[p] = temp[p];
    }
  };

  mergeSort(0, n - 1);
  return ans;
}

复杂度分析 ​

  • 时间复杂度：O(n log n)（归并层数 log n，每层总处理 n）
  • 空间复杂度：O(n)（idx 和 temp 数组）
