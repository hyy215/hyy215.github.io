分治 / 动态规划 / 回溯 / 贪心 ​

Algorithm分治动态规划回溯贪心

这四类方法的代码结构有时很相似，但解决问题的方式不同。可以从四个维度进行区分：

  • 子问题：是否将原问题拆分成子问题，再合并子问题的结果？
  • 重复状态：相同状态是否会反复出现？
  • 候选选择：是否必须枚举不同的选择？
  • 局部选择：当前选择能否被证明为安全？

一、分治法 ​

原理 ​

把原问题拆成若干规模更小、结构相似的子问题，分别求解后再合并结果。分治中的子问题通常彼此独立，各自只需计算一次；DP 面对的子问题则会反复出现，因此需要保存已经算过的结果。

经典形态：归并排序、快速排序、二分查找、最近点对。

解题路径 ​

  1. 确定最简单的情况：明确问题缩小到什么程度时可以直接得到答案，不再继续拆分。
  2. 拆分并求解：把原问题拆成若干规模更小、解法相同的子问题，再递归求解每个子问题。
  3. 合并结果：把各个子问题的答案组合成原问题的答案。这通常是设计分治算法的关键。
  4. 分析复杂度：根据子问题的数量、规模以及合并结果的成本，计算算法的时间复杂度。例如，二分查找是 O(log n)，归并排序是 O(n log n)。
text
divideAndConquer(problem):
    if problem can be solved directly:
        return solve(problem)

    left, right = divide(problem)
    return merge(divideAndConquer(left), divideAndConquer(right))

讲解示例：50. Pow(x, n) ​

计算 x 的 n 次幂，即 xⁿ。直接将 x 连乘 n 次需要 O(n) 时间；利用分治，可以每次把指数缩小一半。

示例 1

输出：1024.00000

输入：x = 2.00000, n = -2
输出：0.25000
解释：2⁻² = 1 / 2² = 1 / 4

约束

  • n 是整数
  • -2^31 <= n <= 2^31 - 1
  • 当 x == 0 时，n > 0

思路

  • 最简单的情况：指数为 0 时，任何非零数的 0 次幂都是 1。
  • 拆分并求解：要求 xⁿ，先递归计算规模缩小一半的 x^⌊n/2⌋。
  • 合并结果：把子问题的结果平方；如果 n 是奇数，还要再乘一个 x。

例如，计算 2¹⁰ 时，不需要连乘十次：

text
2¹⁰
= 2⁵ × 2⁵
= (2² × 2) × (2² × 2)

2
3

左右两半都是同一个子问题，因此只计算一次 2⁵，再将结果平方即可。

ts
function myPow(x: number, n: number): number {
  function fastPow(exponent: number): number {
    if (exponent === 0) return 1;

    // 指数减半，递归求解规模更小的同类问题
    const half = fastPow(Math.floor(exponent / 2));

    // 合并结果：偶数次幂直接平方，奇数次幂还要多乘一个 x
    return exponent % 2 === 0 ? half * half : half * half * x;
  }

  // 负指数先转成正指数，最后取倒数
  const result = fastPow(Math.abs(n));
  return n < 0 ? 1 / result : result;
}

二、动态规划 ​

原理 ​

动态规划先用状态描述子问题，再通过状态转移刻画子问题之间的依赖关系，使每个状态只计算一次。它通常适用于以下场景：

  • 重叠子问题：求解过程中会反复遇到相同的子问题，可以通过记忆化搜索或递推复用已有结果。
  • 可递推求解：当前状态的答案能够由规模更小或已经求出的状态推导出来。

DP 可以避免对同一状态的重复计算，但并不意味着算法一定具有多项式时间复杂度。其总时间复杂度通常取决于状态数量 × 计算每个状态所需的转移成本。

解题路径 ​

  1. 定义状态：dp[i] 或 dp[i][j] 表示什么，要让状态完整描述子问题。
  2. 写转移方程：当前状态如何由之前状态推出，这是 DP 的核心。
  3. 确定初始值：base case 的值，通常是最小规模问题的直接答案。
  4. 确定遍历顺序：确保计算 dp[i] 时所依赖的状态已经计算完。
  5. 空间优化：如果计算当前状态时只会用到前面少数几个状态，就不必保存完整的 dp 数组，只需用几个变量保存仍会用到的值。例如，计算斐波那契数时只需保留前两个数，空间复杂度便可从 O(n) 降到 O(1)。
// 自底向上（表格法）
dp[0] = base
for i in 1..n:
    dp[i] = f(dp[i-1], dp[i-2], ...)
return dp[n]

讲解示例：70. 爬楼梯 ​

爬到楼顶需要走 n 阶楼梯，每次可以爬 1 阶或 2 阶。求爬到楼顶共有多少种不同的方法。

输出：2

示例 2

text
输入：n = 3
输出：3
解释：可以分别爬 1 + 1 + 1 阶、1 + 2 阶或 2 + 1 阶。
1
2
3

约束

  • 1 <= n <= 45

思路

  • 定义状态：dp[i] 表示爬到第 i 阶楼梯的方法数。
  • 初始状态：dp[1] = 1，dp[2] = 2。
  • 状态转移：到达第 i 阶只有两种方式：
    • 从第 i - 1 阶爬 1 阶到达，有 dp[i - 1] 种方法；
    • 从第 i - 2 阶爬 2 阶到达，有 dp[i - 2] 种方法。
  • 转移方程：两种情况互不重复，因此 dp[i] = dp[i - 1] + dp[i - 2]。
  • 遍历顺序：从第 3 阶开始向后计算，保证所依赖的前两个状态已经得到。
ts
function climbStairs(n: number): number {
  if (n <= 2) return n;

  const dp = new Array<number>(n + 1);
  dp[1] = 1;
  dp[2] = 2;

  for (let i = 3; i <= n; i++) {
    dp[i] = dp[i - 1] + dp[i - 2];
  }

  return dp[n];
}

三、回溯法 ​

原理 ​

回溯可以看作在决策树上进行深度优先遍历：

  1. 选择：在当前节点选择一个候选项。
  2. 递归：带着当前选择进入下一层，继续尝试。
  3. 撤销：当前路径无法继续或已经探索完毕时，撤销本次选择并退回上一层，再尝试其他候选项。

当需要枚举指数级规模的候选解时，回溯是常用方法，适合解决“求所有方案、可行方案，以及组合、排列、子集”等问题。

与分治的关系

  • 共同点：两者都经常使用递归。
  • 分治：递归树的分支是需要分别求解并合并结果的子问题。
  • 回溯：递归树的分支是不同的候选选择；当某个选择不满足约束时，可以撤销选择或提前剪枝。

解题路径 ​

  1. 明确决策过程：确定每一层可以做哪些选择，以及一条完整路径代表什么结果。
  2. 定义递归状态：记录当前路径、可选项和剩余约束；根据问题需要加入 start（起始位置）或 depth（当前深度）等参数。
  3. 判断当前路径：如果已经构成完整答案，则收集结果；如果确定无法得到有效答案，则提前结束当前分支。
  4. 执行选择与撤销：依次尝试候选项，做出选择后进入下一层，返回时撤销选择，再尝试其他候选项。
dfs(path, choices):
    if satisfied: collect(path); return
    if impossible: return
    for choice in choices:
        path.add(choice)
        dfs(path, next_choices)
        path.remove(choice)   // 撤销选择

讲解示例：39. 组合总和 ​

给定元素互不相同的整数数组 candidates 和目标值 target，找出所有元素和等于 target 的不同组合，并以任意顺序返回。同一个候选数字可以不限次数地选取；只要至少一种数字的选取次数不同，就视为不同组合。题目保证有效组合少于 150 个。

查看示例与约束

示例 1

text
输入：candidates = [2,3,6,7]，target = 7
输出：[[2,2,3],[7]]

2

示例 2

text
输入：candidates = [2,3,5]，target = 8
输出：[[2,2,2,2],[2,3,3],[3,5]]

示例 3

text
输入：candidates = [2]，target = 1
输出：[]

约束

  • 1 <= candidates.length <= 30
  • 2 <= candidates[i] <= 40
  • candidates 中的所有元素互不相同
  • 1 <= target <= 40

思路

  1. 排序候选数字：先将 candidates 按从小到大排序，为后续剪枝提供条件。
  2. 定义递归状态：start 表示本层可以选择的起始下标，remaining 表示距离目标值还差多少。当 remaining === 0 时，当前路径就是一个有效组合。
  3. 按顺序枚举候选数字：每层只从 start 开始向后选择，使组合中的数字保持固定顺序，避免同时产生 [2, 3] 和 [3, 2] 这类重复组合。
  4. 提前结束无效枚举：如果当前数字已经大于 remaining，那么排在后面的数字也无法选择，可以直接结束本层循环。
  5. 选择、递归并撤销：将当前数字加入路径，递归搜索剩余金额，再在返回时将其移出。递归调用传入 i 而不是 i + 1，表示下一层仍可选择当前数字，从而允许同一个数字被重复使用。
ts
function combinationSum(candidates: number[], target: number): number[][] {
  candidates.sort((a, b) => a - b);
  const res: number[][] = [];
  const path: number[] = [];

  const dfs = (start: number, remaining: number): void => {
    if (remaining === 0) {
      res.push([...path]);
      return;
    }
    for (let i = start; i < candidates.length; i++) {
      if (candidates[i] > remaining) break;
      path.push(candidates[i]);
      dfs(i, remaining - candidates[i]);
      path.pop();
    }
  };

  dfs(0, target);
  return res;
}

三类题型套路：子集 / 组合 / 全排列 ​

子集、组合和全排列是回溯的三类常见题型。它们的主要差异是何时记录答案以及每一层可以选择哪些元素。下面的组合模板以“选出固定数量的元素”为例；如果题目要求满足某个目标值，则需要相应调整记录条件和递归状态。

含义从原数组中选出任意数量的元素从原数组中选出固定数量的元素，且不考虑顺序使用原数组中的所有元素组成不同顺序
记录答案的条件每次进入递归都记录路径长度达到 k路径使用了所有元素
候选范围从 start 开始向后枚举从 start 开始向后枚举每层枚举所有尚未使用的元素
状态参数startstart、kused[]
顺序是否影响答案否否是

子集 — 每层都记录 ​

ts
function subsets(nums: number[]): number[][] {
  const result: number[][] = [];
  const path: number[] = [];

  const backtrack = (start: number): void => {
    result.push([...path]);

    for (let i = start; i < nums.length; i++) {
      path.push(nums[i]);
      backtrack(i + 1);
      path.pop();
    }
  };

  backtrack(0);
  return result;
}

组合 — 凑够 k 个才记录 ​

ts
function combine(nums: number[], k: number): number[][] {
  const result: number[][] = [];
  const path: number[] = [];

  const backtrack = (start: number): void => {
    if (path.length === k) {
      result.push([...path]);
      return;
    }

    const need = k - path.length;
    for (let i = start; i <= nums.length - need; i++) {
      path.push(nums[i]);
      backtrack(i + 1);
      path.pop();
    }
  };

  backtrack(0);
  return result;
}

全排列 — 用 used[] 标记已选元素 ​

ts
function permute(nums: number[]): number[][] {
  const result: number[][] = [];
  const path: number[] = [];
  const used = new Array(nums.length).fill(false);

  const backtrack = (): void => {
    if (path.length === nums.length) {
      result.push([...path]);
      return;
    }

    for (let i = 0; i < nums.length; i++) {
      if (used[i]) continue;

      used[i] = true;
      path.push(nums[i]);
      backtrack();
      path.pop();
      used[i] = false;
    }
  };

  backtrack();
  return result;
}

为什么候选范围不同？ ​

  • 子集和组合不关心顺序：[2, 3] 和 [3, 2] 表示同一种选择。使用 start 限制下一层只能继续向后选择，因此只会生成 [2, 3]，不会再生成 [3, 2]。
  • 全排列关心顺序：[1, 2, 3] 和 [1, 3, 2] 是两个不同答案。每一层都需要检查所有元素，并通过 used[] 排除当前路径中已经使用的下标。

可以根据题目的目标进行判断：

  • 收集任意数量元素形成的所有选择 → 子集。
  • 收集满足指定数量或目标值的选择 → 组合。
  • 相同元素采用不同顺序会形成不同答案 → 全排列。

有重复元素时的去重剪枝 ​

以上模板假设输入元素互不相同。如果输入中存在重复值，需要先排序，再跳过同一层中值相同的元素：

ts
// 组合 / 子集去重（同一层不重复选相同值）
if (i > start && nums[i] === nums[i - 1]) continue;

// 全排列去重（同一层跳过：值相同 且 前一个同值元素未被使用）
if (i > 0 && nums[i] === nums[i - 1] && !used[i - 1]) continue;

四、贪心法 ​

原理 ​

贪心在每一步都做当前看来最优的选择，选定后不再回退。它和 DP 都常用于优化问题，但处理候选选择的方式不同：

  • DP：通常用状态记录并比较不同选择对后续结果的影响。
  • 贪心：依赖某个当前选择是“安全的”，即至少存在一个包含该选择的全局最优解。

贪心的难点不在于实现，而在于证明当前选择不会错：作出这个选择后，仍然能够得到全局最优答案。

经典形态：区间调度、分数背包、哈夫曼编码，以及边权非负图上的 Dijkstra 最短路算法。

解题路径 ​

  1. 找贪心策略：明确每一步按什么规则选择当前候选项，例如最早结束、代价最小或收益率最高。
  2. 证明正确性：证明该选择是安全的，并说明选择后剩余问题仍具有相同结构。
  3. 实现：根据选择规则组织候选项，可能需要排序、线性扫描、优先队列或其他数据结构。
  4. 边界检查：重点检查选择规则、比较方向和候选项更新方式，并用小样例验证。
state = initial_state
while candidates is not empty:
    choice = select_best(candidates, state)
    remove choice from candidates
    if is_feasible(choice, state):
        state = accept(choice, state)
return state

交换论证示例：1029. 两地调度 ​

公司要安排 2n 个人去 A、B 两座城市，每座城市恰好安排 n 人。costs[i] = [aCosti, bCosti] 表示第 i 个人前往两座城市的费用，目标是在满足人数限制的前提下最小化总费用。

输出：110

约束

  • 2 <= costs.length <= 100

贪心策略

  • 对每个人计算费用差 d = aCost - bCost。
  • d 越小，表示相对于去 B，这个人越适合去 A。
  • 按 d 升序排序，让前一半人去 A，后一半人去 B。
ts
function twoCitySchedCost(costs: number[][]): number {
  costs.sort((x, y) => (x[0] - x[1]) - (y[0] - y[1]));

  const half = costs.length / 2;
  let total = 0;

  for (let i = 0; i < costs.length; i++) {
    total += i < half ? costs[i][0] : costs[i][1];
  }

  return total;
}

交换论证是怎么回事？

设方案中有两个人：i 被安排去 A，j 被安排去 B，但他们的费用差满足 d_i > d_j。也就是说，j 相对于 i 更适合去 A，却被安排去了 B。

交换两人的目的地不会改变两座城市的人数。交换前，两人的费用为：

text
a_i + b_j
1

交换后，两人的费用为：

text
b_i + a_j
1

交换带来的费用变化是：

text
(b_i + a_j) - (a_i + b_j)
= (a_j - b_j) - (a_i - b_i)
= d_j - d_i
1
2
3

因为 d_i > d_j，所以 d_j - d_i < 0，交换后总费用更低。因此，最优方案中不可能出现“费用差更大的人去 A、费用差更小的人去 B”这种逆序。

消除所有逆序后，去 A 的必然是费用差最小的 n 个人，去 B 的是其余 n 个人，这正是贪心算法得到的方案。这里通过交换两个选择，并证明交换后可行性不变、结果严格变好，从而排除非最优结构的方法，就是交换论证。

归纳法示例：55. 跳跃游戏 ​

给定一个非负整数数组 nums，最初位于下标 0。nums[i] 表示从下标 i 最多可以向右跳多少步，判断能否到达最后一个下标。

约束

  • 1 <= nums.length <= 10^4
  • 0 <= nums[i] <= 10^5

贪心策略

  • 用 farthest 记录当前能够到达的最远下标。
  • 依次检查每个下标。如果当前下标超过 farthest，说明无法到达这里，也就无法继续向后跳。
  • 如果当前下标可以到达，就用 i + nums[i] 更新最远可达位置。
ts
function canJump(nums: number[]): boolean {
  let farthest = 0;

  for (let i = 0; i < nums.length; i++) {
    if (i > farthest) return false;

    farthest = Math.max(farthest, i + nums[i]);
    if (farthest >= nums.length - 1) return true;
  }

  return true;
}

归纳法是怎么回事？

这里需要证明：每处理完一个可以到达的下标，farthest 始终表示目前能够到达的最远位置。

  1. 处理第一个下标：下标 0 一定可以到达。处理后，最远可以到达 nums[0]，此时 farthest 的含义正确。
  2. 假设处理到前一个下标时是正确的：也就是 farthest 已经准确记录了此前能够到达的最远位置。
  3. 处理当前下标：
    • 如果 i > farthest，当前下标无法到达，算法返回 false。
    • 如果 i <= farthest，当前下标可以到达。从这里最远可以跳到 i + nums[i]，用它更新 farthest 后，farthest 仍然表示目前能够到达的最远位置。

第一步成立，并且从前一步正确能够推出下一步仍然正确，所以这个结论会一直保持到循环结束：只要 farthest >= nums.length - 1，就能到达最后一个下标。这种“先证明第一步成立，再证明每一步都能延续前一步结论”的方法，就是归纳法。
