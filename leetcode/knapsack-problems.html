背包问题：从模型识别到状态转移 ​

Algorithm动态规划背包问题

背包问题研究的是一类受容量约束的选择问题：有若干物品，每件物品会消耗一定容量，并可能带来价值；需要决定选择哪些物品，使选择结果满足容量限制，并得到最大值、最小值、可行性或方案数量等答案。

“背包”和“物品”只是模型中的称呼。题目中的容量可能是金额、时间或数组元素之和，物品也可能是硬币、任务或数字。识别这类问题的关键，是找出选择对象、容量约束、物品使用次数和求解目标。

本文讨论的是容量和物品费用均可表示为非负整数、且物品费用大于 0 的离散背包问题。如果题目使用小数或连续量，需要先判断能否安全地缩放为整数；否则不能直接使用本文的数组下标 DP。

什么是背包问题 ​

经典背包问题可以描述为：有 n 件物品，第 i 件物品的重量为 weight[i]、价值为 value[i]，背包容量为 capacity。在总重量不超过容量的前提下，选择一部分物品，使总价值最大。

这个描述包含三个基本要素：

  • 物品：可以做出的选择；
  • 费用：选择物品需要占用的容量；
  • 目标：选择之后需要最大化、最小化、判断或计数的量。

不同背包模型首先由每件物品可以选择多少次决定；在同一个模型中，题目又可能要求不同类型的答案。这两个维度需要分开判断。

从 0-1 背包建立基本状态 ​

0-1 背包规定每件物品最多选择一次。对第 i 件物品只有两种决策：不选，或者在容量足够时选择。

定义 dp[i][j] 表示：只考虑前 i 件物品，在总重量不超过 j 的情况下，能够得到的最大价值。

  • i 表示已经考虑的物品数量，取值范围是 0 到 n；
  • j 表示当前背包的容量上限，取值范围是 0 到 capacity，不要求物品恰好装满这个容量。

当 i = 0 时没有可选物品，因此对任意容量 j 都有 dp[0][j] = 0。

接下来考虑第 i 件物品。由于 JavaScript 数组从 0 开始编号，它的重量和价值分别是 weight[i - 1] 和 value[i - 1]。对这件物品只有两种选择：

  1. 不选它：

    • 不放入当前物品，背包的容量上限仍然是 j；
    • 答案继承只考虑前 i - 1 件物品时的结果，即 dp[i - 1][j]。

  2. 选它：

    • 选择的前提是背包能装下当前物品，即 j >= weight[i - 1]；
    • 放入当前物品后，剩余容量为 j - weight[i - 1]；
    • 在前 i - 1 件物品中使用这部分容量，能够得到的最大价值为 dp[i - 1][j - weight[i - 1]]；
    • 再加上当前物品的价值 value[i - 1]，就得到选择当前物品时的总价值，即 dp[i - 1][j - weight[i - 1]] + value[i - 1]。

在“不选”和“选择”两种结果中取最大值，就得到状态转移：

text
dp[i][j] = dp[i - 1][j] // 不选

if (j >= weight[i - 1]):
  dp[i][j] = max(
    dp[i][j],
    dp[i - 1][j - weight[i - 1]] + value[i - 1] // 选择
  )

由于每个状态只依赖上一行，因此可以去掉物品维度，把空间从 O(n * capacity) 压缩到 O(capacity)：

js
function knapsack01(weights, values, capacity) {
  const dp = new Array(capacity + 1).fill(0);

  for (let i = 0; i < weights.length; i++) {
    for (let j = capacity; j >= weights[i]; j--) {
      dp[j] = Math.max(dp[j], dp[j - weights[i]] + values[i]);
    }
  }

  return dp[capacity];
}

压缩成一维 DP 后，同一个数组既保存上一轮的状态，也用来写入当前轮的状态。更新 dp[j] 时，右侧的 dp[j - weights[i]] 必须仍是上一轮的结果，这样才能保证当前物品最多只选一次。

因此，0-1 背包的容量必须从大到小遍历。由于 j - weights[i] 小于 j，更新 dp[j] 时，dp[j - weights[i]] 还没有在当前轮被修改，读取的仍然是只考虑之前物品时的结果。

例如，当前物品的重量为 2、价值为 3，且 dp 初始全为 0。如果容量正序遍历：

  1. 先更新 dp[2] = dp[0] + 3 = 3，此时 dp[2] 已经包含当前物品；
  2. 再更新 dp[4] = dp[2] + 3 = 6，就会再次读取当前轮刚写入的 dp[2]，相当于把同一件物品选了两次。

如果改为倒序遍历，会先更新 dp[4]。此时 dp[2] 还是上一轮的结果，不包含当前物品，因此不会重复选择。

时间复杂度为 O(n * capacity)，空间复杂度为 O(capacity)。这里的复杂度依赖容量的数值，因此经典背包 DP 属于伪多项式算法，而不是关于输入二进制长度的多项式算法。状态与复杂度的完整推导可参考 MIT 6.006 的背包问题讲义。

常见背包模型 ​

三种核心模型的区别在于物品的使用次数：

模型每种物品可选次数一维 DP 的容量方向常见处理方式
0-1 背包最多一次从大到小直接转移
完全背包无限次从小到大让当前物品的结果继续参与本轮转移
多重背包最多 count[i] 次取决于转换方式枚举数量或拆成若干件 0-1 物品

在最大价值问题中，0-1 背包和完全背包压缩后可以使用相同的转移式：

text
dp[j] = max(dp[j], dp[j - weight] + value)
1

真正改变含义的是遍历方向：

  • 0-1 背包倒序遍历，读取的是使用当前物品之前的状态；
  • 完全背包正序遍历，允许读取本轮已经加入当前物品的状态，因此可以继续选择它。

在 0-1 背包、完全背包和多重背包这三种核心模型之外，还有一些由约束关系扩展出的类型：

  • 混合背包：不同物品分别遵循 0-1、完全或多重背包规则；
  • 二维费用背包：同时受到两种容量限制，例如时间和预算；
  • 分组背包：物品被划分为若干组，每组最多选择一件；
  • 依赖背包：选择某件物品之前必须先选择它所依赖的物品。

这些变体不会在这里展开实现。它们仍然围绕同一个问题修改状态：做出当前选择时，必须额外记录哪些约束。

  • 1 <= nums[i] <= 100

这道题要把数组分成元素和相等的两份。设数组元素总和为 sum，如果 sum 是奇数，总和无法均分，因此可以直接排除。剩下的问题是：数组中是否存在若干个元素，它们的和恰好为 sum / 2。

令 target = sum / 2，将问题对应到背包模型：

  • 物品：数组中的每个元素；
  • 物品重量：元素的数值；
  • 背包容量：target；
  • 选择限制：每个元素只能选或不选，不能重复使用，因此属于 0-1 背包；
  • 求解目标：判断能否选出若干个元素，使元素和恰好等于 target。

遍历过程中，只要发现 dp[target] 为 true，就说明存在一组元素的和为 sum / 2。由于所有元素的总和为 sum，剩余未选元素的和必然也是 sum / 2，因此不需要再单独查找另一个子集。

定义 dp[j] 表示能否从已经处理的数字中选出若干个，使它们的和恰好为 j：

js
var canPartition = function (nums) {
  const sum = nums.reduce((total, num) => total + num, 0);
  if (sum % 2 !== 0) return false;

  const target = sum / 2;
  const dp = new Array(target + 1).fill(false);
  dp[0] = true;

  for (const num of nums) {
    for (let j = target; j >= num; j--) {
      dp[j] = dp[j] || dp[j - num];
    }
  }

  return dp[target];
};

完全背包示例：零钱兑换 I 与 II ​

322. 零钱兑换：求最少硬币数 ​

给定不同面额的硬币数组 coins 和总金额 amount，返回凑成总金额所需的最少硬币数；无法凑成时返回 -1。每种面额的硬币都可以无限次使用，因此该题属于完全背包。

约束

  • 1 <= coins.length <= 12
  • 1 <= coins[i] <= 2^31 - 1
  • 0 <= amount <= 10^4

  1. 定义状态：dp[j] 表示凑出金额 j 所需的最少硬币数。

  2. 初始化金额 0：dp[0] = 0，表示凑出金额 0 不需要硬币。

  3. 初始化其他金额：其余 dp[j] 初始化为 Infinity，表示对应金额当前还无法凑出。

  4. 确定遍历顺序：外层遍历每种硬币 coin，内层从 coin 到 amount 正序遍历金额 j。

    • 硬币放在外层，表示逐种考虑可以使用的硬币；
    • 金额在内层正序遍历，计算 dp[j] 时可以读取当前轮已更新的 dp[j - coin]，因此同一种硬币可以重复使用。

  5. 状态转移：如果使用一枚当前硬币，需要先凑出 j - coin，再加上当前硬币，所需硬币数为 dp[j - coin] + 1。在原结果与新结果中取较小值：

    text
    dp[j] = min(dp[j], dp[j - coin] + 1)
    1

遍历结束后，如果 dp[amount] 仍为 Infinity，说明无法凑出目标金额，返回 -1。

js
var coinChange = function (coins, amount) {
  const dp = new Array(amount + 1).fill(Infinity);
  dp[0] = 0;

  for (const coin of coins) {
    for (let j = coin; j <= amount; j++) {
      dp[j] = Math.min(dp[j], dp[j - coin] + 1);
    }
  }

  return dp[amount] === Infinity ? -1 : dp[amount];
};

  1. 定义状态：dp[j] 表示使用已经处理过的硬币种类，凑出金额 j 的组合数。

  2. 初始化金额 0：dp[0] = 1，表示不选择任何硬币是凑出金额 0 的一种组合。

  3. 初始化其他金额：其余 dp[j] 初始化为 0，表示对应金额当前还没有可行组合。

  4. 确定遍历顺序：外层遍历硬币 coin，内层从 coin 到 amount 正序遍历金额。

    • 硬币放在外层，按硬币种类逐轮更新 dp，使每个组合只被计数一次；
    • 金额在内层正序遍历，使同一种硬币可以重复使用。

  5. 状态转移：每个凑出 j - coin 的组合，加入一枚当前硬币后，都会形成一个凑出 j 的组合，因此：

    text
    dp[j] += dp[j - coin]
    1

JavaScript 实现 ​

js
var change = function (amount, coins) {
  const dp = new Array(amount + 1).fill(0);
  dp[0] = 1;

  for (const coin of coins) {
    for (let j = coin; j <= amount; j++) {
      dp[j] += dp[j - coin];
    }
  }

  return dp[amount];
};

322 与 518 的异同 ​

两道题的物品都是硬币，背包容量都是目标金额，每种硬币都可以重复使用。因此，它们都可以采用“外层遍历硬币、内层正序遍历金额”的完全背包写法。

两者的主要区别在于初始值和状态转移：

  • 322 求最少硬币数：dp[0] = 0，其余为 Infinity，转移时取最小值；
  • 518 求组合数：dp[0] = 1，其余为 0，转移时累加方案数。

能否改为外层遍历金额 ​

如果改为外层正序遍历金额 j、内层遍历硬币 coin：

  • 322 可以这样写。计算 dp[j] 时，内层枚举最后加入的硬币，并在所有 dp[j - coin] + 1 中取最小值。硬币的选择顺序不会改变最少硬币数，因此结果不变。
  • 518 不能直接交换循环顺序。金额放在外层时，内层会枚举每个组合最后加入的硬币，于是 1 + 2 和 2 + 1 会被计为两种方案，得到的是排列数，而不是题目要求的组合数。

解法：转换为 0-1 背包 ​

多重背包规定第 i 种物品最多选择 count[i] 次。最直接的方法是在处理每种物品时枚举使用数量：

js
for (let i = 0; i < items.length; i++) {
  const { weight, value, count } = items[i];

  for (let j = capacity; j >= weight; j--) {
    const maxCount = Math.min(count, Math.floor(j / weight));

    for (let k = 1; k <= maxCount; k++) {
      dp[j] = Math.max(dp[j], dp[j - k * weight] + k * value);
    }
  }
}

这种写法容易理解，但物品数量很大时会产生大量重复枚举。为了减少枚举次数，可以把多件相同物品捆成几个“物品组”，每组再作为一件物品参与 0-1 背包。

接下来的关键是：如何用尽量少的物品组，表示从不选到全选的所有数量？ 二进制分组正是为了解决这个问题。

二进制分组是怎么推导出来的 ​

拆分的目标是：用尽量少的物品组，表示从 0 到 count 的任意选择数量。

二进制的每一位分别代表 1、2、4、8……，也就是 2^0、2^1、2^2、2^3……。一个数在某一位上是 1 还是 0，可以理解为“选择”或“不选择”对应数量的物品组。因此，将物品拆成 1、2、4、8…… 件一组，就可以通过选择不同的组，组合出范围内的任意数量。

例如，0..7 中的任意数量都可以由 1、2、4 组合得到：5 = 1 + 4，6 = 2 + 4，7 = 1 + 2 + 4。

如果某种物品最多有 13 件，先依次取出 1、2、4 件，此时还剩 6 件；由于不足下一组的 8 件，将剩余的 6 件作为最后一组：

text
1 + 2 + 4 + 6 = 13
1

1、2、4 可以表示 0..7；加上可选的 6 件组后，又可以表示 6..13。两个范围合起来覆盖 0..13 的所有数量。

如果原物品的重量为 weight、价值为 value，包含 take 件物品的组就被视为一件重量为 weight * take、价值为 value * take 的新物品。由此类推，对拆分后的每个物品组分别做“选”或“不选”，就可以表示选择原物品的不同数量，并得到这些数量对应的总重量和总价值。

  • 转换后的模型：拆分后的每组最多选择一次，因此可以统一使用 0-1 背包的倒序容量转移。
  • 分组数量：数量为 count[i] 的物品最多拆成 floor(log2(count[i])) + 1 组。
  • 时间复杂度：将数量为 0 的情况一并纳入表达后，整体时间复杂度为 O(capacity * sum(log(count[i] + 1)))。
  • 进一步优化：还可以使用单调队列优化，本文不再展开。

js
function splitItems(weight, value, count) {
  const groups = [];
  let batch = 1;
  let remaining = count;

  while (remaining > 0) {
    const take = Math.min(batch, remaining);
    groups.push({
      weight: weight * take,
      value: value * take
    });
    remaining -= take;
    batch *= 2;
  }

  return groups;
}

将拆分后的物品组依次执行 0-1 背包转移，就得到完整实现：

js
function multipleKnapsack(items, capacity) {
  const dp = new Array(capacity + 1).fill(0);

  for (const { weight, value, count } of items) {
    const groups = splitItems(weight, value, count);

    for (const group of groups) {
      for (let j = capacity; j >= group.weight; j--) {
        dp[j] = Math.max(dp[j], dp[j - group.weight] + group.value);
      }
    }
  }

  return dp[capacity];
}
