深入理解 Manacher 算法：高效计算回文子串个数 ​

AlgorithmManacher回文

Manacher 算法 可在 O(n) 时间内解决「最长回文子串」「回文子串个数」等问题，核心是利用回文的 对称性，通过扩展与对称推导避免暴力重复计算。该算法得名于 Glenn K. Manacher 在 1975 年发表的线性时间回文识别算法；本文讲解的是常见的回文半径数组实现。

本文以 647. 回文子串 为例，说明如何套用 Manacher 求解回文子串个数。以下实现遵循题目约束，输入字符串仅包含小写英文字母。

例题：647. 回文子串 ​

给定字符串 s，统计其中回文子串的数量。同一段字符如果出现在不同位置，需要分别计数；子串必须由原字符串中的连续字符组成。

约束

  • s 只包含小写英文字母

什么是回文？ ​

回文指正序与逆序完全一致的字符串，例如 aba、abba。长度可为奇数或偶数：

  • 奇数长度回文：如 aba，以 b 为中心，两侧对称。
  • 偶数长度回文：如 abba，左右对称。

统一奇数与偶数回文的处理 ​

为消除奇偶差异，在字符间插入 #，用同一套「以某位置为中心扩展」的方式处理：

  • 奇数长度回文：以原字符为中心。
  • 偶数长度回文：以 # 为中心。

例如：

  • aba → #a#b#a#
  • abba → #a#b#b#a#

代码：构造辅助串 ​

ts
s = `#${s.split('').join('#')}#`;
1

定义回文半径数组 P ​

回文半径：以中心字符为轴，向任意一侧延伸的字符数（不含中心本身）。使用 P[i] 记录每个位置能扩展的最大半径。

以 #a#b#b#a# 为例，其中一个回文子串是 #b#，中心是 b，其回文半径为 1。

初始化 P 存储每个下标的回文半径：

ts
const P = new Array(s.length).fill(0);
1

找规律 ​

手动补全半径可得下表：

序号012345678
字符#a#b#b#a#
P010141010

观察：

  • 半径即原串回文长度：P[i] 恰好等于该中心对应的原串回文长度。例如索引 4 处半径为 4，对应原串回文 abba 长度为 4；索引 1 处半径为 1，对应原串回文 a 长度为 1。这是插入 # 后的构造性质。
  • 镜像初值：在已知的最大回文范围内，关于中心对称的两个位置，其半径存在关联。例如，在上表中，整个回文的中心是下标 4，下标 3 和 5 关于它对称，二者的半径均为 1；计算右侧下标 5 时，可以复用 P[3] 作为初值。这正是 Manacher 利用的核心性质，见下节。

计算右侧位置 i 的回文半径 ​

已知左侧对称点的半径后，可给右侧赋初值，减少从头扩展的次数。

对称关系 ​

中心为 center，当前下标 i 关于 center 的对称下标为 2 * center - i，对称点半径为 P[2 * center - i]。

text
center - left = i - center
=> left = 2 * center - i
1
2

右边界限制 ​

镜像半径不能超过当前对称关系所在的回文范围。因此，P[i] 的初值最多只能取 right - i；超出右边界的部分需要继续比较。

图 1：当前位置的初始半径取对称点半径与右边界距离的最小值。由 OpenAI 图像生成工具生成于 2026-08-10。

右侧对称点初始值 ​

所以，P[i] 的初值取对称点半径 P[2 * center - i] 与右边界距离 right - i 的最小值。

ts
if (i < right) {
  P[i] = Math.min(P[2 * center - i], right - i);
}

扩展回文半径 ​

在确定初始值后，以 [i - P[i], i + P[i]] 为起点，向两侧扩展直到字符不等，查找当前点的最大对称半径

ts
// 继续扩展回文
let leftIndex = i - P[i] - 1;
let rightIndex = i + P[i] + 1;
while (leftIndex >= 0 && rightIndex < s.length && s[leftIndex] === s[rightIndex]) {
  P[i]++;
  leftIndex--;
  rightIndex++;
}

更新中心与右边界 ​

  • i + P[i] 超过当前 right
  • 说明发现了更大的回文范围
  • 则更新 center 与 right，供后续位置复用对称信息：
ts
if (i + P[i] > right) {
  center = i;
  right = i + P[i];
}

为什么时间复杂度是 O(n)？ ​

辅助串共有 2n + 1 个位置，每个位置作为中心处理一次。

while 每成功扩展一次，right 就向右移动。由于 right 不会回退，整个算法中成功扩展的总次数最多约为 2n，而不是每个中心都执行 2n 次。

因此，总操作次数可以理解为：

text
遍历所有中心 + 所有中心的扩展次数
≈ (2n + 1) + 2n
= O(n)
1
2
3

所以，即使 while 写在 for 内部，两者的执行次数也不是相乘关系。辅助串和数组 P 的空间复杂度都是 O(n)。

统计回文子串个数 ​

P[i] 记录的是辅助串中的回文半径，但题目需要原字符串中的回文子串数量。

同一中心下，辅助串的半径每增加 2，就会在原串中多得到一个回文子串。例如：

text
P[i] = 1：a，共 1 个
P[i] = 3：b、aba，共 2 个
P[i] = 4：bb、abba，共 2 个
1
2
3

因此，某个中心贡献的回文子串数量为 Math.ceil(P[i] / 2)，等价写法是 Math.floor((P[i] + 1) / 2)。

最后将所有中心贡献的数量相加：

ts
return P.reduce(
  (sum, radius) => sum + Math.floor((radius + 1) / 2),
  0
);

完整代码 ​

ts
function countSubstrings(s: string): number {
  s = `#${s.split('').join('#')}#`;
  const P = new Array(s.length).fill(0); // 回文半径

  let center = 0; // 回文中心点
  let right = 0; // 当前最右回文的包含式右边界
  for (let i = 0; i < s.length; i++) {
    if (i < right) {
      P[i] = Math.min(P[2 * center - i], right - i);
    }

    let leftIndex = i - P[i] - 1;
    let rightIndex = i + P[i] + 1;
    while (leftIndex >= 0 && rightIndex < s.length && s[leftIndex] === s[rightIndex]) {
      P[i]++;
      leftIndex--;
      rightIndex++;
    }

    if (i + P[i] > right) {
      center = i;
      right = i + P[i];
    }
  }

  return P.reduce((a, b) => a + Math.floor((b + 1) / 2), 0);
}

总结 ​

Manacher 结合回文对称与中心扩展，把时间复杂度降到 O(n)，适合回文子串计数、最长回文子串等场景；通过维护 P、center、right 可避免大量重复扩展。
